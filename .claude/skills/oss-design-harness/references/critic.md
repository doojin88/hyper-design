# C단계 서브에이전트 지시문

아래 두 지시문은 **서로 다른 새 서브에이전트**에게 준다. `{shots}`만 스크린샷 폴더 경로로 바꾸고 나머지는 그대로 쓴다. 지시문에 PRD 내용, 설계 의도, 기대하는 답을 덧붙이지 않는다.

## 이해 테스트

```
{shots} 폴더에 어떤 서비스의 화면 스크린샷(.mobile.png, .desktop.png)이 있다.
너는 이 서비스를 처음 보는 비개발자다. 코드나 다른 문서는 읽지 말고 스크린샷만 Read로 열어 본다.
파일 이름 순서대로 모든 .mobile.png 를 보고, .desktop.png 는 3장 이상 본다.

다음에 답한다.
1. 이 서비스는 무엇을 하는 서비스인가 (2문장)
2. 누가 쓰는가 — 화면에서 구별되는 사용자 종류를 모두 적고, 각자 이 서비스로 무엇을 하는지 한 줄씩
3. 이 서비스가 없을 때 사용자가 겪었을 불편은 무엇으로 보이는가
4. 화면만 보고는 뜻을 알 수 없었던 말·기호·색 구분 (파일 이름과 함께)
5. 다음에 무엇을 눌러야 할지 알 수 없었던 화면 (파일 이름과 함께)

추측한 부분은 "추측"이라고 표시한다. 좋게 말해 줄 필요 없다.
```

## 결함 판정

```
{shots} 폴더에 어떤 서비스의 화면 스크린샷(.mobile.png 390px, .desktop.png 1280px)이 있다.
너는 현업 제품 디자이너로서 이 화면들의 결함을 찾는다. 먼저 {visual} 을 읽고 그 기준으로 판정한다.
코드는 읽지 않는다. 모든 스크린샷을 Read로 열어 본다.

아래 항목마다 결함을 찾는다.
- 색온도·톤이 화면 사이에서 흔들리는가
- 화면마다 1차 행동이 3초 안에 보이는가
- 간격 순서(섹션 > 카드 > 카드 안 > 요소)가 지켜지는가, 같은 종류 카드의 간격이 화면마다 같은가
- 정보가 번잡하거나, 반대로 PC 폭에서 휑하게 늘어났는가
- 상투적 표현(기준 문서의 "상투")이 있는가
- 빈 상태·마감 임박 같은 엣지 화면이 완성돼 있는가
- 한 역할의 화면에 다른 역할의 메뉴·정보가 보이는가
- 글자가 잘리거나 어색하게 줄바꿈되는가, 요소가 겹치거나 화면 밖으로 나가는가
- 아이콘·그림 크기가 어긋나는가

결함마다 한 줄로 적는다:
[blocker|major|minor] [국소|구조] <파일 이름> — 무엇이 어떻게 보이는지 → 어떻게 고치면 되는지

blocker: 화면을 쓸 수 없거나 깨져 보임 / major: 한눈에 어색하거나 기준 문서를 어김 / minor: 다듬으면 좋은 정도
결함이 없는 항목은 적지 않는다. 마지막 줄에 "blocker n · major n · minor n"을 적는다.
```
