# Decisions — 가족여행 앱 v2

## 식별된 독립 축
- 축 1: 정보 구조(역할별 뷰를 어떻게 가르나)
- 축 2: 상태·알림 정책
- 축 3: 밀도·접근성
- 축 4: 비주얼 무드(토큰 한 벌로 확정)

## 축 1 — 정보 구조
| 후보 | 설명 | 비교 근거 | 선택 |
|---|---|---|---|
| A. 같은 화면 + 필터 | 한 일정 화면에서 "가족에게 보이는 것만" 토글 | 부모가 복잡한 화면에 노출됨. 부모 조작이 늘어남 | ✕ |
| B. 역할별 완전 분리 화면 | 계획자용 편집 / 가족용 열람 두 앱 | 부모 화면을 통째로 단순화 가능. 시연도 쉬움 | ✓ |
| C. 계획자 화면 안 미리보기 패널 | 편집 중 옆에 가족 화면 미리보기 | 좋지만 모바일에서 좁음 → B의 보조로 "가족에게 보임/숨김" 표시만 채택 | 보조 |
**선택 이유**: 가장 불편한 사용자(67세 부모)에게 화면을 통째로 단순화하려면 B. 계획자에겐 항목별 노출 표시(C의 축약)를 준다.

## 축 2 — 상태·알림 정책
| 후보 | 설명 | 비교 근거 | 선택 |
|---|---|---|---|
| A. 모든 변경 즉시 알림 | | 후보 고칠 때마다 울림 → 자녀가 편집을 꺼림 (PRD 갈등 그대로) | ✕ |
| B. 확정 변경만 묶음 | 큐에 쌓아 1건으로 | 부담 최소. 다만 항공·숙소 변경이 늦게 가면 위험 | 기본 |
| C. B + 중요 변경 즉시 예외 | 이동·숙박·집합만 즉시 | 안전과 조용함을 둘 다 잡음 | ✓ |
| + 부모의 "궁금해요" | 부모→자녀 역방향 신호, 목록으로만 | 부모가 묻기 미안한 문제를 직접 해결 | ✓ 추가 |
**선택 이유**: C + 역방향 신호. 양쪽 배려 문제를 양방향으로 푼다.

## 축 3 — 밀도·접근성
- 부모: 탭 3개, 본문 18px(큰 글씨 22px), 요약 카드 3줄 + "외 n개", 터치 타깃 56px.
- 계획자: 밀도 높게(항목 행에 상태·도구 한 줄).

## 교차 비평
- **PRD 사용자(67세 아버지)**: 궁금할 때 물어볼 방법이 없음 → "궁금해요" 채택. 바뀐 곳이 어디인지 몰라 헤맴 → 소식에 전후 표기 + 하루 상세에 "바뀐 곳" 표시.
- **구현·검증**: 확정→큐→발송→수신→확인, 궁금해요→계획자 목록 두 플로우 모두 단일 HTML에서 시연 가능.

## 남은 트레이드오프
- 즉시 알림 예외 기준(이동·숙박·집합)이 고정이라 세밀한 설정은 못 준다.
- "궁금해요"가 남용되면 소음이 될 수 있어, 같은 항목은 한 사람당 1회만 받는다.
